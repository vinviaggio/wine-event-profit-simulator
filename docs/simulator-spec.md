# ワインイベント採算シミュレータ 仕様書（正本）

本ドキュメントは、`index.html`（v1.0.0時点）に実際に実装されている仕様の記録である。
本Repositoryのmain branchと本仕様書がSource of Truthであり、変更時は本仕様書を壊さないこと。
AIに修正を依頼する場合は、まず最新mainと本仕様書を確認させること。

対象イベントモデル: 第1部 試飲会 ＋ 第2部 ペアリングワイン会（現在はD'Argento Croce基準）。
ワインボトル容量は 750ml/本 固定。

## 1. 基本原則

1. CASE A は理論・保守モデル（追加開栓本数を自動計算）。
2. CASE B は実運用・手動設定シナリオ（追加開栓本数を完全手動設定）。
3. 採算計算と物理判定（ワイン量の充足判定）は完全に独立している。
4. CASE B の追加開栓本数は完全手動設定（スライダー 0〜6本）。
5. 過去実績の追加開栓本数は参考表示のみ（第2部人数に応じて「過去実績 0本程度 / 0〜1本程度 / 2〜3本程度」をバッジ表示）。計算ロジックには一切使用しない。

## 2. 入力項目と範囲（初期値）

| 項目 | 範囲 | 初期値 |
|---|---|---|
| 第1部参加人数 | 5〜15名 | 12名 |
| 第1部試飲銘柄数 | 6〜13銘柄 | 12銘柄 |
| 第1部実消費率 | 50〜100%（5%刻み） | 80% |
| 第2部参加人数 | 5〜12名（上限は第1部人数に追従） | 8名 |
| 第2部使用銘柄数 | 3〜6銘柄 | 5銘柄 |
| 第2部1人当たり提供目安量 | 50/60/70/80/90/100ml ボタン | 80ml |
| 平均希望小売価格 | 1,600〜4,000円（100円刻み） | 2,750円 |
| 仕入率 | 55〜75% | 65% |
| 第1部参加費 | 3,500〜5,000円（500円刻み） | 4,000円 |
| CASE B追加開栓本数 | 0〜6本 | 1本 |

制約: 第2部参加人数は第1部参加人数を超えない（第1部人数を減らすと第2部人数の上限・現在値が自動でクランプされる）。

詳細設定（アコーディオン）: 第2部使用銘柄ごとに「実測残量(ml)」と「追加ボトル割当(本)」を入力できる。銘柄配列は第2部使用銘柄数に同期（増えれば追加、減れば末尾切り捨て）。

## 3. 共通計算式

- 1本あたり仕入原価 = 平均希望小売価格 × 仕入率
- 第1部1銘柄あたり消費量 = 第1部人数 × 50ml × 実消費率
- 第1部1銘柄あたり推定残量 = 750ml − 上記消費量
- 第2部1銘柄あたり必要量 = 第2部人数 × 提供量(ml)
- グラス原価 = 第1部人数 × 1,100円
- 料理原価 = (第2部人数 + 1) × 5,500円（ホスト1名分を含む）
- 売上(11,000円案) = (第1部人数 − 第2部人数) × 第1部参加費 + 第2部人数 × 11,000円
- 売上(12,000円案) = (第1部人数 − 第2部人数) × 第1部参加費 + 第2部人数 × 12,000円
- イベント利益 = 売上 − (ワイン原価 + グラス原価 + 料理原価)
- 利益率 = 利益 ÷ 売上 × 100
- 12,000円案と11,000円案の利益差は常に 第2部人数 × 1,000円 と一致する。

## 4. CASE A（理論・保守モデル）

- 銘柄ごとの追加必要量 = max(0, 第2部必要量 − 第1部推定残量)
- 銘柄ごとの追加開栓本数 = ceil(追加必要量 ÷ 750ml) — 銘柄ごとの不足を満たすまで750ml単位で追加開栓
- 総追加開栓本数 = 銘柄ごと追加本数 × 第2部使用銘柄数
- 総開栓本数 = 第1部試飲銘柄数 + 総追加開栓本数
- CASE A は常に充足（不足が出ない設計）。
- 開栓後の余剰量を表示する（銘柄あたり余剰 = 推定残量 + 追加開栓量 − 必要量、およびその合計）。
- 追加ボトル750mlは特定の1銘柄へ割り当てる前提。750mlを複数銘柄へ均等分配しない。

## 5. CASE B（実運用・手動設定シナリオ）

- 総開栓本数 = 第1部試飲銘柄数 + 手動設定追加開栓本数
- 利益表示は手動設定シナリオに基づく「試算利益」である。
- 採算計算は物理判定の状態に関わらず、現在手動設定中の追加開栓本数を即時使用する（割当不一致状態でも同じ）。

## 6. 物理判定（3段階）

判定モードは以下の順で決まる（実装ロジック通り）:

1. 実測残量の入力が0銘柄 → 【均一残量参考判定】(uniform)
   全銘柄が第1部推定残量（均一）であると仮定して総量判定。
2. 実測残量が全対象銘柄で揃い、かつ（追加開栓本数が0本 または 銘柄別割当合計が設定本数と一致）→ 【実測残量による厳密判定】(strict)
3. それ以外（実測が一部のみ、または割当合計が不一致）→ 【実測未完備参考判定】(incomplete)

判定の計算:

- 利用可能総量 = Σ(銘柄ごとの残量: 実測値があれば実測値、なければ推定残量) + 現在設定中の追加開栓本数 × 750ml
- 主表示の総量判定は常に「現在設定中の追加開栓本数」を使用する。
- 割当合計が設定本数と異なる場合、旧割当ベースの総量は補助表示のみ（auxiliary）。
- 銘柄別判定（充足/不足）は割当一致時のみ実施。不一致時は銘柄別判定を行わない。

## 7. 割当不一致時の処理（重要）

- CASE B追加開栓本数を変更しても、既存の銘柄別割当を自動削除・自動再配分しない（ユーザー入力を保持）。
- 設定追加本数と割当合計が不一致の場合、厳密判定から実測未完備参考判定へ降格する（実測が全銘柄揃っている場合）。
- 不一致状態でも採算計算・物理判定の主表示は、現在手動設定中の追加開栓本数を即時使用する。
- 旧銘柄別割当に基づく総量は補助表示のみ。

## 8. グラフ（Chart.js）

1. 第2部参加人数別 CASE A / CASE B 利益比較（11,000円案・12,000円案）
2. 第2部参加人数別 CASE A 追加開栓本数
3. CASE B 追加開栓本数（0〜6本）感度分析
- 第1部人数を減らした場合、第2部人数のグラフ範囲上限も追従する。

## 9. UI機能

- 初期化ボタン: 全入力値を初期値に戻し、銘柄別詳細入力（実測残量・割当）もクリアする。
- 詳細設定アコーディオンの開閉。
- 目標利益（20,000円 / 30,000円）との差分表示。
- サマリーコメント（採算・物理充足の総合評価文）を自動生成・表示。
